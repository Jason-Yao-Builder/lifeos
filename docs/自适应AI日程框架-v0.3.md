# LifeOS 自适应 AI 日程框架 v0.3

## 结论

🔴 AI 不拥有任务事实，只拥有“提出候选变更”的权利。任务、依赖、日历和事件日志是真相账本；AI 运行、候选卡片和待验证记忆是假设账本。两者只能通过“预览 → 确定性校验 → 人工确认 → 原子提交”相连。

这一版没有把旧的温度或综合分换成更复杂的分数。排序采用字典序：先保证截止与依赖，再保持近期承诺，其次考虑目标关联、人工顺序和时间块适配。理由随每个安排一起返回。

## 一次计划如何发生

1. 读取带版本号的任务快照、双向依赖、可用时间窗和已完成耗时。
2. 复盘记忆先做训练集/留出集检验；少于 8 个样本只保留候选，误差未下降至少 10% 则拒绝晋升。
3. 截止压力沿依赖链反向传播，避免普通任务挤占“必须先准备才能按时交付”的工作。
4. 冻结时域内的既有承诺保持原位；新任务只填空隙。冻结块冲突时返回不可行。
5. 编译器输出 `adaptive-schedule` 提案，不修改任务。
6. 用户接受时重新读取最新版本，复验截止、重叠和依赖；任一项失败则整个事务回滚。
7. 成功提交后，每个任务变更与 AI 运行继续进入已有追加式事件日志。

具体场景：09:00 有“准备材料”，10:00 有“提交方案”且后者依赖前者；另有一项人工排在最前的普通任务。编译器先把 10:00 的截止压力传给“准备材料”，因此安排顺序是“准备材料 → 提交方案 → 普通任务”，而不是机械服从人工 rank 导致迟交。

## 组件

| 组件 | 职责 | 禁止事项 |
|---|---|---|
| Breakdown Compiler | 校验 2—12 个子任务、完成定义、估时和无环依赖 | 不直接创建任务 |
| Adaptive Ranker | 按硬风险、稳定性、目标、人工顺序和适配度排序 | 不输出伪精确综合分 |
| Constraint Scheduler | 在显式时间窗内排程，传播依赖截止，保护冻结时域 | 不在容量外“挤入”任务 |
| Approval Gate | 复验版本、截止、重叠和依赖 | 不接受过期或不可行提案 |
| Memory Gate | 用留出样本验证估时校准 | 不把单次感想写成长期规则 |
| Evaluation Runner | 聚合场景通过率、安全率、稳定率和解释覆盖率 | 不用单一平均分遮蔽硬失败 |

## API

- `POST /api/v1/ai/plan-preview`：输入时间窗、可选授权任务集、旧计划与冻结边界；返回计划提案、记忆检验结果和确认卡片。
- `POST /api/v1/ai/breakdown-preview`：输入模型或用户生成的拆解草案；返回经过编译的子任务图和确认卡片。
- `POST /api/v1/cards/:id/decision`：接受时原子应用计划或拆解；拒绝或校验失败时不写任务。

## 迭代中发现的失败

1. 初版只看任务自身截止，普通任务会挤压有截止的后续任务；改为沿 DAG 反向传播有效截止。
2. 初版在基准误差为 0 时无法表达“校准使结果变差”；改为明确负收益并拒绝记忆晋升。
3. 仅计算 churn 不能阻止 churn；增加冻结时域，把稳定性变成硬约束。

## 研究依据

- 🟢 [ReAct: Synergizing Reasoning and Acting in Language Models](https://arxiv.org/abs/2210.03629)：把推理与行动分开记录，为“提案而非直接写入”提供了代理结构依据。
- 🟢 [Reflexion: Language Agents with Verbal Reinforcement Learning](https://arxiv.org/abs/2303.11366)：说明反思可作为后续尝试的显式上下文；本框架额外增加留出验证，防止未经证实的反思晋升。
- 🟢 [Voyager: An Open-Ended Embodied Agent with Large Language Models](https://arxiv.org/abs/2305.16291)：可复用技能库启发了“候选记忆 → 验证 → 晋升”的分层生命周期。
- 🟢 [Google OR-Tools Scheduling](https://developers.google.com/optimization/scheduling)：硬约束优先、不可行性显式返回的工程范式。

## 已知边界

🔴 当前是单用户、本地 SQLite 的框架实验；尚未接真实生成模型、外部日历、多人资源容量、随机中断和概率耗时分布。拆解端点负责验证模型草案，不负责调用特定模型。下一阶段应先加入真实历史回放与盲测集，再比较不同模型、Skills 和 Workflow；不能用演示数据上的 100% 冒充现实世界完成率。
