# 用户数据与源码分离

## 默认位置

LifeOS 不再把正式数据写入源码仓库。默认 SQLite 文件：

- macOS：`~/Library/Application Support/LifeOS/lifeos.db`
- Windows：`%APPDATA%/LifeOS/lifeos.db`
- Linux：`${XDG_DATA_HOME:-~/.local/share}/lifeos/lifeos.db`

可用 `LIFEOS_DATA_DIR` 改变用户数据目录，或用 `DATABASE_URL` 指向一个明确的数据库文件。命令行维护工具仍可用 `--database <path>` 临时指定。

## 数据归属

| 数据 | 正式模式 | Demo 模式 |
|---|---|---|
| 任务、分组、目标、附件、依赖、重复计划、复盘 | SQLite | 浏览器 `localStorage`；图片仅当前页面会话内存 |
| AI 运行、卡片、对话和消息 | SQLite | 浏览器 `localStorage` 中的卡片数据 |
| 自动化规则设置 | SQLite | 浏览器 `localStorage` |
| 一键顺延目标日期 | 浏览器 `localStorage` | 浏览器 `localStorage` |
| API 端口、时区、调试 key、跨域配置 | 进程环境变量 | 不适用 |

当前 AI adapter 是本地 deterministic 实现，没有外部模型密钥。以后接入真实模型时，密钥只能放在环境变量或系统密钥链，不能写入数据库、源码或前端构建变量。

## Git 安全

仓库忽略 `data/`、SQLite 文件、`.env` 及其常见变体；只保留脱敏的 `.env.example`。首次推送前可运行：

```bash
git ls-files | rg '(^|/)(data/|.*\.(db|sqlite|sqlite3)(-|$)|\.env)'
```

正常结果只允许出现 `.env.example`。备份用户数据时应直接备份用户数据目录，不要把数据库复制回仓库。
